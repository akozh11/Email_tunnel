# Email_tunnel

Мост между почтовым ящиком (или несколькими) и Gemini: письма-запросы
обрабатываются нейросетью, ответ отправляется обратно строго тому
отправителю, от которого пришёл запрос.

## Установка

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка

1. Скопируйте `.env.example` в `.env` и заполните реальными данными
   (пароли/токены приложений для IMAP/SMTP, ключ `GEMINI_API_KEY`).
2. Отредактируйте `config.json`: опишите каждый ящик в массиве `accounts`.
   Поля `mail_user` / `mail_pass` и т.п. можно указывать как `${VAR_NAME}` —
   значение будет подставлено из `.env`.

Ключевые поля аккаунта в `config.json`:

| Поле | Описание |
|---|---|
| `self_only` | `true` — обрабатывать только письма, которые ящик отправил сам себе (как в исходной версии проекта); `false` — обрабатывать письма от любых внешних отправителей |
| `reply_mode` | `append_inbox` — дописать ответ в тот же INBOX; `smtp` — реально отправить письмо через SMTP на адрес отправителя |
| `process_backlog_on_first_run` | обрабатывать ли всю существующую в ящике историю писем при первом запуске (для внешних ящиков рекомендуется `false`, чтобы не разослать ответы на всю старую переписку) |
| `max_replies_per_sender_per_hour` | ограничение на количество ответов одному адресату в час (защита от петель) |

## Запуск

```bash
python main.py
```

Каждый аккаунт из `config.json` опрашивается в собственном потоке со своим
интервалом (`poll_interval_seconds`) — сбой или задержка одного ящика не
блокирует остальные. Остановка — `Ctrl+C`.

Состояние опроса (последний обработанный UID и т.п.) хранится в `state/*.json`
и не требует ручного обслуживания.
